#### Perfil Dataform
- **Estructura:** `workflow_settings.yaml` (o `dataform.json`: `defaultProject`, `defaultLocation`, `defaultDataset`, `defaultAssertionDataset`, `dataformCoreVersion`), `definitions/` (declaraciones de fuentes `type: "declaration"`, staging, intermedios, marts) e `includes/` (constantes y funciones JS). Referencias siempre con `${ref("...")}` / `${resolve("...")}`; nunca `proyecto.dataset.tabla` fijo.
- **Compilar antes de ejecutar:** `dataform compile` es gratis y detecta ciclos/refs rotas. Para ejecutar usa `dataform run --dry-run` o acciones concretas con `--actions`; **no ejecutes ni reprogrames workflows de producción (release/workflow configs) sin aprobación expresa**.
- **Entornos:** separa dev/prod por proyecto de GCP o con `schemaSuffix`/`tablePrefix` y `vars` de compilación; nunca escribas en datasets de producción desde un workspace de desarrollo.
- **Calidad:** usa `assertions: { nonNull, uniqueKey, rowConditions }` en cada tabla relevante y aserciones manuales para reglas de negocio; las aserciones que fallan se investigan, no se quitan.
- **Incrementales:** `type: "incremental"` con `uniqueKey` y `updatePartitionFilter`; una *full refresh* (`--full-refresh`) sobre tablas grandes requiere aprobación (costo de bytes procesados y ventana de datos).
- **Versiones y seguridad:** `@dataform/core` fijado en `package.json`/`dataformCoreVersion`; sus subidas por vulnerabilidad se registran con el CVE/GHSA en el commit. Credenciales de cuenta de servicio fuera del repo (ADC / identidad del servicio de Dataform).
- **Despliegue:** "desplegado" = el release config compiló ese commit **y** el workflow config de producción terminó bien. Regístralo con `memory_deploy.py record <entorno>` solo tras verificarlo. Guarda en la memoria: grain, partición/clustering, dueño y SLA de cada tabla, y la línea base de bytes por ejecución.
