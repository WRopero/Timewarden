#### Data graph and connections (data projects)

- **Structure and lineage: query the graph, do not guess and do not grep model by model.** `python3 -I <MS>/scripts/data_graph.py impact|upstream|downstream|show|find|path <node>` answers exactly and offline (what a model reads, who consumes it, what breaks if it changes). Use `check` for cycles, unresolved/dynamic refs, layer skips and test coverage. Semantic questions (why, business meaning) go to `recall`; the graph documents live in `docs/agent-memory/data-graph/`. Human-written rules go in `docs/agent-memory/data-graph/rules.md` (never overwritten).
- **Connections: read `docs/agent-memory/connections.md` (source: `.agent-memory/connections.yaml`) before asking the user how to connect.** It lists per environment the system, auth method, env var NAMES, identifiers and ready-to-run validate/explore/dry-run commands, and what is forbidden without approval. `data_connect.py check` shows which tools and variables exist on this machine. Never write credentials into the catalog or memory. Fill any `TODO` you can verify.
- **Keeping it current is automatic:** the session-start hook fingerprints the repo (and, only for environments with `metadata_sync: true`, a cheap live signature) and rebuilds and re-indexes only what changed. After a large refactor run `python3 -I <MS>/scripts/data_sync.py run --force` once. Live sync is read-only and metadata-only.
