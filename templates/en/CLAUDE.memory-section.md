## Project memory (Cognee)

- Canonical source: `docs/agent-memory/*.md` (Git). Cognee is only a derived index. Identity in `.agent-memory/project.yaml` (`project_id: __PROJECT_ID__`).
- **Query memory when the briefing is not enough** (you don't know what happened, why something was decided, or something looks new): query BEFORE asking the user or assuming. Skill `project-memory-recall` / MCP `agents_cognee` `recall` with `datasets="__PROJECT_ID__-knowledge"` (string), `search_type="CHUNKS"`, `top_k=3`. Querying is cheap (no LLM); do not repeat the same question or query what the briefing or this file already says. Freshness: `memory_stale.py` (no code reading).
- **Commit and keep the main branch up to date (mandatory):** when closing every task or milestone, and before calling a session done, leave everything saved in Git: commit code and memory (`docs/agent-memory/`, `.agent-memory/*.json`, `openspec/`, `CLAUDE.md`) on a branch following the project's workflow, open a PR and, with checks green, merge into the main branch; then update it locally (`git pull --ff-only`). Always start from the latest tip of the main branch. The briefing flags uncommitted changes and drift from `origin`: act on it. Forbidden: `push --force`, committing secrets or locally excluded files (`.agent-memory/local.yaml`, `handoffs/_local/`, `.claude/settings.local.json`), and skipping hooks or CI. If the project's workflow differs (e.g. direct commits to the main branch), follow that.
- **Deployments:** the briefing shows which commit is deployed per environment and which branches/commits are missing (`.agent-memory/deployments.json`). **After deploying and verifying health** record it: `python3 -I <MS>/scripts/memory_deploy.py record . <env> --commit <sha> --note "..."` (never before verifying; a branch not merged into the main branch or not an ancestor of what is deployed is reported as NOT deployed).
- **Session continuity (automatic):** on open/resume/compact a hook injects a briefing (~1,000 tokens) built from `docs/agent-memory/` and Git; on close/compact another hook saves a checkpoint (`handoffs/_local/auto-<branch>.md`). That briefing is already context: do not query it again.
- **When a task ends or the user says "wrap up"/"done for today":** skill `project-memory-handoff` and, if a lasting decision was made, `project-memory-document` + `<MS>/scripts/memctl.sh sync . --apply` **once per task/milestone** (each new chunk costs ~2 Claude calls).
- If the stack does not respond (`memctl.sh status`), read `docs/agent-memory/` directly; do not block the work.
- **When ambiguous, query first:** if a requirement, a design decision or a "why is it like this" is not clear from the loaded context, BEFORE deciding, assuming or asking, query the memory (`recall`, CHUNKS, top_k 3; it includes OpenSpec specs and changes) and check freshness. Ask the user only if the ambiguity remains.
- **OpenSpec drives every implementation or change (mandatory):** any new feature, behavior change, non-trivial refactor or data/infrastructure change goes through an OpenSpec change: `/opsx:propose` (proposal + specs + design + tasks) -> the user reviews -> `/opsx:apply` (implement the tasks) -> `/opsx:archive`. Do not write product code without an active change (the briefing lists them); exceptions: typos, formatting, comments and urgent hotfixes (document them afterwards with a change). Before proposing, query the memory and the current specs; specs are the source of truth for behavior and, if code and spec differ, ask. After archiving a change run `memctl.sh sync . --apply` once.
- **Security and versions:** the briefing lists open vulnerabilities (automatic OSV audit on session start, at most every 24 h) and `docs/agent-memory/security/dependencias.md` keeps versions, change history and pending items. When bumping a dependency for security, name the CVE/GHSA in the commit; do not ignore critical ones silently; to accept a risk use `.agent-memory/security-ignore.txt`.
- `<MS>` = path of the memory system (`memory_system` field of `.agent-memory/local.yaml`, local to each machine).
- **Forbidden**: `forget` with `everything`, deleting datasets, `docker compose down -v`, storing credentials or real sensitive data in memory. Never query other projects' datasets.

### When compacting the conversation
Keep: goal, constraints, decisions and their source, test results, pending work and next action.
